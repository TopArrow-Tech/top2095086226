# 衣改 FitNote 全阶段实现方案

## 背景与目标

用户授权全阶段开发，并选择暖米白、墨绿、少量黄铜色，要求专业高级的定制页面。产品定位为本地试衣修改与工艺交接，不扩展 ERP。

## 技术方案

确认现有项目只有 PHP manifest 模板，没有既有业务组件；按运行规则选用已验证的 TopArrow Node 24.20.0 / SQLite 3.53.4。采用 React / TypeScript、SVG、SQLite 版本快照、离线 PDF 与 ZIP 备份。

分阶段完成：启动及架构 → 工作台/列表/新建/设置 → 十张模板和标注 → 持久化与历史 → PDF → 照片、对比、备份、打包及错误处理。每阶段结合类型检查、存储测试、HTTP 验收和实际界面检查验证。

## 体验调整

用户试用后反馈处理单据较复杂，已把日常路径简化为客户及服装 → 图纸修改 → PDF 交接。新建表单将编号、日期、联系信息、经办人和备注收进补充资料；项目编辑将工艺、口径、状态按需展开，保留“完成此项，继续标记”。

## 涉及文件

src、server、public、scripts、tests、manifest.json、icon.png、build、licenses，以及 _doc 项目、变更和测试文档。AGENTS.md 保持只读未改。

## 注意事项

用户数据只写环境变量目录。开发 data 不随包发布。独立服务与完整前端构建纳入版本库。无联网资源，无云服务器，无付费 AI API。完整字体嵌入保证中文可靠，接受 PDF 文件相对较大。

发布前需补 Windows 实机验证、英文名称冲突检查，并执行平台正式发布自检；本次不上传市场或推送远程。
