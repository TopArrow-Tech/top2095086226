# 试衣与数据架构

## 编辑与保存

界面维护当前草稿和最多 100 步撤销/重做记录；动作、字段修改、项目排序和照片标注都可撤销。标记拖动的一整个手势只占一个撤销步骤。

修改后约 950ms 防抖保存，保存请求串行执行；界面明确显示未保存、保存中、已保存和失败。离开编辑器前先尝试保存，失败时使用应用内弹层告知丢失风险。关闭窗口使用 beforeunload 提示（具体呈现由平台 WebView 决定）。

数据库保存采用 BEGIN IMMEDIATE 事务，revision 乐观锁拒绝旧窗口覆盖更新。编号唯一约束失败会回滚整次保存。

## 版本

版本状态为 draft/final。定稿后拒绝写入，只有最新定稿可创建下一次试衣。新版本复制完整业务快照，修改项目 ID 沿用以追踪历史，版本 ID 和版本序号独立。试衣资料、坐标、照片标注随版本保存，不从最新资料反向渲染历史单。

版本比较按项目 ID 判断新增、调整、取消、完成；差异界面保留前值和跨所有版本的轨迹。处理状态为待处理、修改中、已完成、需复核；取消为独立标志。

## 坐标与模板

模板 SVG 原始 viewBox 为 0 0 480 620。点击通过 getScreenCTM 的逆变换回到原图坐标，再除以宽高存为 0～1。窗口变化通过 ResizeObserver 自动计算适应比例，缩放只影响显示。

正反面共享项目编号，排序与编号分离。同一部位可建立多个项目。图纸外保留余量，编号不因自动适应而难以阅读。PDF 对边缘编号做向内偏移和引线，定位点保持原始归一化位置。

v1 服装模板为随包原创示意图，后续新增 v2 时保留已有 v1 资源，避免旧版本图纸变化。

## 照片

只接收 JPG、PNG、WebP，单张上限 15MB，界面检查可解码及像素上限。服务器检查文件签名，生成 UUID 文件名。数据库只保存 photos 下的相对路径。

圈选区域保存归一化矩形范围，界面与导出画为椭圆；说明与关联项目单独保存，原图不修改。丢失文件显示错误状态，导出明确报错。移除照片不删除其他历史版本仍引用的原图；备份只打包数据库实际引用的附件。

## PDF

按需加载生成库与预览器。完整嵌入本地中文字体，规避当前字体子集化时部分字形丢失；因此单份 PDF 通常约 6MB 起。图纸在浏览器以 3 倍分辨率合成，明细文字保留 PDF 文本。按实际字体宽度换行、逐段分页，附页重复单号及版本标识。照片长边压缩到最多 1800 像素后合成标注。

预览用随包 PDF.js 渲染 canvas，不依赖系统 PDF 插件。Worker 固定从 /pdf-worker.js 加载，静态服务同时为 .js 和 .mjs 提供 JavaScript MIME。PDF 写入 exports；用户可另行下载。重复导出同名同版本文件会更新导出文件，不修改历史业务数据。

## 归档删除

只有归档单允许永久删除。确认弹层明确提示单号、全部历史和独占照片将删除且无法撤销。核对单号及记录指纹后事务删除单据和版本；只清理不再被其他记录引用的照片。清理失败独立提示。删除不会自动生成备份，需要保留数据时用户可先手动备份。

## 运行安全与跨平台

只绑定 TOPARROW_APP_PORT 的 127.0.0.1。拒绝非法 Host、跨 Origin 请求，写接口要求自定义头；静态资源不暴露用户数据根目录。API 附件只能使用受约束的相对路径。生产服务已打包纯 JS 依赖，包内无 .node 原生插件。

路径使用 node:path；无固定用户目录和端口，无系统脚本或系统字体依赖。Windows 实机仍需验证下载、文件名、打印、平台启动行为。

## 归档管理与中英切换（2026-11-10）

侧栏提供独立归档管理入口及数量，与普通修改单列表隔离。归档页保留搜索、服装筛选、状态筛选与日期排序，直接显示文字恢复按钮。打开归档单后返回到归档页；恢复后重新进入普通单据列表，试衣版本、照片及项目不变。归档本身不删除数据；独立删除操作见上文“归档删除”。

语言文件在 src/locales/zh-CN.json 与 en-US.json，固定文案集中管理；domain-keys.json 约束可翻译的标准业务值。src/i18n.ts 使用 useSyncExternalStore 通知界面更新，无需刷新或重建编辑器。语言存入 SQLite settings.locale，由右上角和设置页即时保存。新增设置无需变更数据库结构。

已有数据库中的服装类型、动作、状态等规范值保持原样，不做数据迁移；展示时翻译，英文标准部位及动作输入反向映射到原规范值。客户姓名、服装自定义名称、工艺说明与备注不自动翻译。错误提示根据集中消息表翻译。

PDF 在导出开始时固定语言快照，避免生成途中切换产生混合固定文案；中文使用本地嵌入字体，ASCII 使用 PDF 标准 Helvetica，英文按单词换行。确认栏根据实际换行高度预留位置。文件名随服装类型的显示语言生成。

## 手动业务备份与恢复

设置页提供全局手动备份；无启动、保存、删除、定时或恢复前自动备份。GET /api/backups 只扫描磁盘，不创建目录；POST /api/backups 才创建 backups 并生成独立 .fitbackup。名称为本机日期时间加随机后缀，包含完整 SQLite 快照与所有被历史引用的照片，保留归档、标注、设置和版本。无源码、日志、PDF 或递归备份。

先取得 node:sqlite 一致快照，压缩至临时文件，重新读取并按 SHA-256 清单校验后原子改名。失败清理临时 SQLite 及 WAL/SHM，不列为成功。最多 200MB 文件、400MB 解压、10000 项；空间和权限错误单独提示。

列表不维护额外数据库；外部删除文件后刷新或重新聚焦页面即消失。DELETE /api/backups/:name 只删受约束的普通文件，拒绝符号链接、外部路径和未知名称；POST /api/backups/:name/open-folder 通过随包 Electron 辅助进程打开固定所在目录，缓存及日志仍在数据根。

POST /api/backups/import 接收用户选择的 .fitbackup 文件。界面明确告知整库替换、不合并、不会自动备份。先校验路径、文件哈希、格式、SQLite 完整性与关联、表列结构、迁移版本、业务文档与设置。附件只新增，不覆盖冲突文件；失败清理本次新增附件，数据库事务回滚。使用 ATTACH 和事务替换业务表，不直接覆盖活动数据库，不改变接收方数据根。revision 提升以拒绝旧编辑窗口迟到写入；备份及恢复期间拒绝写入，读取请求体后再次校验维护状态。

Windows 与 macOS 使用 node:path 和顶箭 Electron 的 shell.openPath，无外部网络资源。Windows 实机仍需验证目录打开与文件选择。

## 服装扩充
燕尾服 tailcoat、T恤衫 tshirt 纳入前端 garmentTypes/typeKeys/parts 与服务端类型校验。均提供 v1 正反面 SVG，原始 viewBox 仍为 480×620；共七类十四张模板。燕尾服补充驳头、前衣长、燕尾，T 恤衫补充下摆等部位；标准词纳入中英域映射。既有模板字节不变，PDF 与备份恢复沿用通用逻辑。
